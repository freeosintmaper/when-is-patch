# Когда патч?

**Трекер версий Dota 2: Public, Staging, Experimental и признаки скорого обновления**

[🌐 Открыть сайт](https://freeosintmaper.github.io/when-is-patch/) · [🐛 Сообщить о проблеме](https://github.com/freeosintmaper/when-is-patch/issues)

</div>

## 📖 О проекте

Небольшой сайт для игроков в **Dota 2**, которые хотят понимать, когда ждать следующее обновление. Valve **никогда не объявляет даты патчей заранее** — но по косвенным признакам можно оценить, что происходит.

Сайт следит за тремя ветками клиента Dota 2:

| Ветка | Что это | Что показывает |
|---|---|---|
| 🔶 **Public** | Игра, в которую играют все | Номер клиента, обновляется часто |
| 🔴 **Staging** | Закрытая служебная ветка Valve | Оживает перед крупными патчами |
| 🟣 **Experimental** | Внутренняя «кухня» Valve | Меняется почти каждый день, фон |

На основе этих данных сайт показывает **уровень активности**: «Пока тихо» / «Есть сигнал» / «Активность выше обычной» / «Высокая активность».

> ⚠️ **Важно:** сайт не предсказывает дату патча. Он показывает признаки и сравнивает текущую ситуацию с прошлой. Valve анонсирует патч **в момент выхода**.

---

## ✨ Что показывает сайт

- **Текущие версии** всех трёх веток клиента
- **Вердикт** — сводная оценка активности индикаторов, без обещания даты патча
- **Сигналы** — пауза после патча, активность Staging, справочная активность Experimental
- **Последний официальный патч** — номер, дата выхода и количество прошедших дней
- **Актуальность данных** — время последнего успешного сбора и статус свежести снимка
- **Хронология** — поиск по версии, фильтр по ветке и просмотр дополнительных записей
- **Сводка** — копирование текущих версий и времени проверки в буфер обмена
- **Часовой пояс** — время проверки показывается в локальном часовом поясе посетителя

## 🛠️ Как это работает

```
┌─────────────────────┐    ┌────────────────────┐    ┌─────────────────┐
│  GitHub Actions     │───▶│  update.js         │───▶│  data.json      │
│  (по расписанию)    │    │  Node.js скрипт    │    │  history.json   │
└─────────────────────┘    └────────────────────┘    └────────┬────────┘
                                                               │
                                                               ▼
                                                    ┌─────────────────────┐
                                                    │  index.html         │
                                                    │  GitHub Pages       │
                                                    └─────────────────────┘
```

### Источники данных

- **Список патчей** — официальный API Dota 2: `dota2.com/datafeed/patchnoteslist`
- **Версии веток** — открытый репозиторий [muk-as/DOTA2_WEB](https://github.com/muk-as/DOTA2_WEB), который агрегирует данные SteamDB
- **История** — накапливается в `history.json` при каждом запуске

### Надёжность сбора данных

Сборщик проверяет HTTP-ответы, тайм-ауты, структуру JSON и наличие всех трёх версий. Если официальный список патчей или хотя бы одна ветка недоступны, обновление завершается ошибкой **до публикации новых файлов**. Предыдущие `data.json` и `history.json` остаются на месте — пустой или неполный снимок не должен затирать рабочие данные.

Workflow дополнительно проверяет синтаксис `update.js` и валидность сгенерированных JSON-файлов перед коммитом. Запуски сериализованы, чтобы два одновременных обновления не перезаписывали историю друг друга.

### Как считается вердикт

Скрипт сравнивает текущую ситуацию с прошлыми наблюдениями. Это эвристика, а не инсайдерская информация и не статистически гарантированный прогноз:

| Сигнал | Что значит |
|---|---|
| 🟢 **Staging молчит** | Обычная ситуация |
| 🔴 **Staging недавно менялся** | Косвенный признак активности, сам по себе ничего не подтверждает |
| 🔴 **Пауза дольше медианы** | Текущий интервал длиннее исторического типичного интервала |
| 🟢 **Experimental меняется** | Справочный фон; не используется как самостоятельный сигнал скорого релиза |

**0 сигналов** → «Пока тихо» · **1** → «Есть сигнал» · **2 и более** → «Активность выше обычной». Даже высокий уровень не означает, что патч выйдет сегодня или завтра.

## 📁 Структура репозитория

```
when-is-patch/
├── index.html                    # Страница (GitHub Pages)
├── update.js                     # Скрипт сбора данных
├── data.json                     # Текущий снимок (создаётся автоматически)

├── README.md                     # Этот файл
└── .github/
    └── workflows/
        └── update.yml            # GitHub Actions — расписание
```


## 🚀 Как развернуть свой

1. **Fork** этот репозиторий (кнопка сверху).
2. Зайди в **Settings → Pages**, выбери:
   - Source: **Deploy from a branch**
   - Branch: **main** / **(root)**
   - **Save**
3. Зайди в **Actions → Update Patch Data → Run workflow**.
4. Через минуту открой `https://твой-username.github.io/when-is-patch/`.

## 📅 Частота обновления

Данные обновляются **автоматически примерно каждые 15 минут** через GitHub Actions. GitHub может задерживать плановые запуски, поэтому на сайте есть отдельный индикатор актуальности. Кнопка «Перезагрузить данные» перечитывает опубликованные JSON-файлы, но не запускает новый workflow.

Версии веток и история смен растут со временем. Историческая выборка помогает сравнивать активность с прошлым, но не гарантирует точность прогноза.
